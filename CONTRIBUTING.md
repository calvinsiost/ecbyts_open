# Contributing to ecbyts_open

Thanks for your interest in contributing to **ecbyts** — Open Architecture
for Trusted Environmental and Occupational Digital Twins. This public
repository runs entirely in **Guest Mode** (no backend); please read the
[README](./README.md) first to understand what works locally and what is
disabled by design.

By participating you agree to the [Code of Conduct](./CODE_OF_CONDUCT.md).

## Environment setup

- **Node.js 22.14.0** — pinned in [.nvmrc](./.nvmrc) and `package.json`
  `engines`. With `nvm`, run `nvm use` to pick it up.
- **Git**, and a GitHub account to open pull requests.

```bash
git clone https://github.com/calvinsiost/ecbyts_open
cd ecbyts_open
npm install
npm run build     # REQUIRED before the first start — compiles src/ to app/js/
npm start         # serves the app on http://localhost:4000
```

The build step is mandatory: `app/js/` is generated output and is not
committed. Skipping it makes the app show an `ERR_BUILD_MISSING` screen.

## Running the tests

```bash
npm test          # runs the published test suite (node --test)
npm run leak:scan # verifies the tree ships no secrets/PII (must be clean)
```

A pull request is only mergeable when `npm run build`, `npm test` and the
CI workflow (see [.github/workflows/ci.yml](./.github/workflows/ci.yml)) are
all green.

## Code standards

- **TypeScript-first.** The source of truth is `src/app/js/**/*.ts`. The
  `app/js/**/*.js` mirror is DERIVED (generated by `npm run build`) — never
  edit it by hand.
- **No frameworks.** This is intentionally vanilla TypeScript/JS (Three.js
  for 3D). Do not add React, Vue, a bundler, or similar.
- **No emojis in the UI.** Use SVG icons or HTML entities.
- **No personal data, no secrets.** Never commit credentials, API keys,
  tokens, real e-mail addresses, real client data, or local machine paths.
  Demo/example data must be 100% synthetic. The `leak:scan` gate blocks
  these in CI.
- Keep functions small (~30 lines), document public functions with JSDoc,
  and prefer descriptive English names.

## Pull request flow

1. **Fork** the repository and create a topic branch:
   `git checkout -b feat/short-description`.
2. Make your change on the canonical `.ts` sources; add or update tests.
3. Run `npm run build`, `npm test` and `npm run leak:scan` locally.
4. Open a **Pull Request** against `main` and fill in the
   [pull request template](./.github/PULL_REQUEST_TEMPLATE.md) checklist.
5. Wait for **CI to pass** (build + test). A red run blocks the merge.

Use the [issue templates](./.github/ISSUE_TEMPLATE/) to report a bug or
request a feature before large changes, so scope can be agreed up front.

## Security issues

Do **not** open a public issue for a vulnerability. Follow the
[Security Policy](./SECURITY.md) and report privately through GitHub Security
Advisories.
